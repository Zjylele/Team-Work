# 首版页面原型设计

用户已授权先制作一版，再提出修改意见。本稿为方案演示，不代表需求最终确认或业务功能已实现。

2026-11-03 补充：原型仍是待评审演示。其中的待验收、三个角色名（团队管理员、项目负责人、普通成员）和成员只读，以 [[01-需求与设计/首版使用范围]] 为准。已确认的用法是：创建者管理项目、阶段和任务分配；成员可查看全部内容，并只能向前更新自己任务的状态、补充说明和评论。

## 设计假设

- 一个固定团队空间，管理多个项目；多团队切换尚待确认。
- 用户角色先分团队管理员、项目负责人、普通成员；当前演示未实现权限隔离。
- 任务状态采用待开始、进行中、待验收、已完成，流转规则待确认。
- 页面使用左侧导航、浅色优先且支持宿主深色主题的布局。

## 页面与交互

- 工作台：我的待办、进行中项目数、待验收数量及示例动态。
- 项目空间：项目卡片，进入“协作系统开发”示例项目；第二项目仅展示。
- 项目详情：看板/列表切换，标题搜索和负责人筛选。
- 任务详情：修改状态、负责人、截止日期、优先级，发表评论。
- 我的任务：展示分配给当前演示用户的任务。
- 团队成员：展示三位成员及职责。
- 消息通知：查看关联任务、全部标为已读。
- 个人设置：资料表单交互演示。
- 新建任务：填写标题、负责人和截止日期，提交后进入看板。

## 边界

原型使用本地演示数据，不连接 Java 后端或 MySQL。刷新后不保留操作。没有登录、真实消息推送、文件上传、创建项目或成员邀请功能。任务详情使用页面内展开面板，待评审后可调整为右侧抽屉。

演示项目完成进度由示例任务计算；另一项目和最近动态为静态示例，不表示实时聚合。

## 评审重点

导航和信息密度是否合适；任务卡片字段是否足够；状态是否需要“待验收”；团队模式和角色划分是否符合实际使用。
